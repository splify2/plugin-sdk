# steer-api 1.4 — что добавлено к 1.3

Ядро steer 2.1 (ветка с этим полем) говорит steer-api **1.4**. Это прибавка к [steer-api.md](steer-api.md) (1.0) и
[1.1](steer-api-1.1.md)–[1.3](steer-api-1.3.md): плагин, написанный по 1.0–1.3, работает без изменений. Плагину с
новым полем пишут `compat.steer-api: "^1.4"`; ядро отвечает `steer version --json` с `"api":"1.4"`.

Появилось по нужде плагина `box-connector`: sing-box для podkop и forkop работает внутри единственного `steerd`
(службы ядра), а не своим экземпляром. Метки podkop (`0x00100000`, `0x00200000`) и forkop
(`0x01000000`…`0x08000000`) лежат в битах поля метки steer по умолчанию и ставятся целиком — ядру с соседями нужно
другое поле, порядок правил и возврат решения. Раньше это задавал второй `steerd` переменными окружения.

## Настройки платформы: `steer.platform`

```json
"steer": {
  "platform": { "mark_field": "0x000000ff", "rule_pref": 100, "mark_restore": true, "router_self": true }
}
```

| Ключ | Тип | Что | Переменная ядра |
|---|---|---|---|
| `mark_field` | строка | поле метки steer: биты подряд, не больше 16 | `STEER_MARK_FIELD` |
| `rule_pref` | число 1–32765 | приоритет `ip rule` выходов steer | `STEER_RULE_PREF` |
| `mark_restore` | да/нет | вернуть решение steer пакету, чью метку чужая цепочка переписала целиком (`prerouting_restore`, dstnat + 10) | `STEER_MARK_RESTORE` |
| `router_self` | да/нет | трафик самого роутера к адресам из списков — по тем же правилам, что LAN | `STEER_ROUTER_SELF` |

Как ведёт менеджер (steer `src/pluginmgr/pminst.c`, «steer.platform»; `src/platform/platform.c`, `plat_setting`):

- **Файл.** При установке, обновлении, снятии, включении и выключении плагина менеджер собирает ключи всех
  **включённых** плагинов в `/etc/steer/plugins/platform.env` строками `ПЕРЕМЕННАЯ=значение`. Никто не просит —
  файла нет.
- **Кто читает.** Каждый процесс ядра — `steerd`, `steer apply`, `status`, `check`: одно поле метки у всех.
  Переменная окружения сильнее файла (стенды, ручной запуск).
- **Смена.** Поле метки процесс ядра берёт при старте, поэтому смена файла поднимает службу ядра заново
  (`/etc/init.d/steer restart`).
- **Два плагина.** Разные значения одного ключа — действует плагин, стоявший раньше; второй ставится с
  предупреждением, которое называет обоих и оба значения.
- **Ядро старше 1.4** поле не знает, поэтому плагин с `steer.platform` пишет `compat.steer-api: "^1.4"`
  (`s2p lint` отказывает при диапазоне, в который входит 1.3).

Образец — [`examples/box-connector`](../examples/box-connector/plugin.json).
