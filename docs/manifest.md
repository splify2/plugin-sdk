# Манифест плагина `plugin.json`

Спецификация v1 (schema 1). Схема — [`schema/plugin.schema.json`](../schema/plugin.schema.json), образцы —
[`examples/`](../examples). Адреса `файл:строка` сняты с деревьев хаба на 2026-10-25: steer `9f0e1fd`,
splify2 `91ac6d2`.

Манифест лежит в корне архива `.s2p` (см. [s2p.md](s2p.md)) и после установки — в
`/usr/lib/steer/plugins/<id>/plugin.json`. Его читают:

- менеджер плагинов в `steer-core` — при установке, обновлении, отборе по совместимости и при каждом
  старте `steerd` (реестр видов, подкоманд, служб и хуков);
- splify2 — для UI, rpc, ACL и раздела «Плагины»;
- `s2p lint` в SDK — до выпуска.

## Общие правила

- **Неизвестные поля пропускаются**, неизвестная `schema` — отказ. Новое поле добавляется без новой
  `schema`, если старый менеджер может его не знать без вреда. Поле, без понимания которого плагин
  работает неправильно, поднимает `schema`.
- **Пути в манифесте — внутри каталога плагина** (`$defs/relpath`): без `/` в начале и без `..`.
  Абсолютные пути бывают только в `keep`, `requires.kernel` и в правах `fs:`.
- **Имена глобальны.** `id`, имена видов, подкоманд и служб занимают одно пространство на роутере, из
  какого бы репозитория плагин ни пришёл. Второй плагин с занятым именем не ставится, а отказ
  называет занявший плагин и его репозиторий («подкоманда warp-scan уже есть у warpbox из splify2»).
  Почему не `<repo>/<id>` — [open.md](open.md), О-6.
- **Тексты для человека** (`name`, `description`, `help`, `texts.*`) — по правилу хаба: состояние и
  действие, без технических пояснений. Переводы — в `i18n/<язык>.json` плагина под ключами
  `plugin.name`, `plugin.description`, `command.<имя>.help`, `kind.<имя>.label`.

## Поля верхнего уровня

| Поле | Обяз. | Что |
|---|---|---|
| `schema` | да | `1` |
| `id` | да | `[a-z0-9][a-z0-9-]*`. Становится каталогом `/usr/lib/steer/plugins/<id>`, объектом ubus `splify2.p.<id>`, цепочками nft `plugin_<id>_<слот>` и `p_<id>_<набор>` |
| `version` | да | semver плагина |
| `type` | нет | `plugin` (умолчание), `library`, `language`, `theme` — подсказка каталогу и интерфейсу; права от неё не зависят. У `library` есть `libs`, и её снимают, только когда на неё не ссылается ни один стоящий плагин |
| `name`, `description` | `name` — да | для человека |
| `license` | нет | SPDX. Плагин с `.so` в `steerd` (раздел `steer.so`) — производная работа steer (GPL-3.0, `steer/LICENSE`): `s2p lint` отвергает несовместимую лицензию у плагина с `so` |
| `homepage`, `authors` | нет | |
| `compat` | да | теги совместимости, раздел ниже |
| `arch` | да | `"all"` (нет машинного кода) или список пакетных архитектур OpenWrt |
| `requires` | нет | зависимости: плагины, системные пакеты, проверки ядра Linux |
| `conflicts` | нет | плагины, с которыми этот не ставится рядом |
| `permissions` | нет | заявленные права, раздел ниже |
| `resources` | нет | метки, очереди, порты, таблицы на весь плагин |
| `steer` | нет | точки расширения ядра: виды, подкоманды, службы, хуки, nft, `.so` |
| `rpc` | нет | методы для splify2 (объект ubus `splify2.p.<id>`) |
| `splify2` | нет | точки расширения каркаса splify2: хуки, задачи, события, псевдонимы и переопределения методов, настройки ([splify2-api.md](splify2-api.md)) |
| `ui` | нет | ES-модуль панели |
| `i18n` | нет | словари плагина; у `type: language` — ещё словари хоста |
| `themes` | нет | темы панели (только переменные и CSS) |
| `libs` | нет | только у `type: library`: общие библиотеки для других плагинов |
| `variant` | нет | вариант сборки: `full` (умолчание) или `lite` — облегчённый для мини-роутеров |
| `standalone` | нет | вариант работает и без `steer-core`: своё мини-ядро и обновление себя |
| `keep` | нет | что переживает sysupgrade и снятие без `--purge` |
| `scripts` | нет | `postinst`, `prerm`, `migrate` |
| `health` | нет | `timeout_s` проверки здоровья после установки и обновления, умолчание 60 |

## `compat`: теги совместимости

`compat` — объект «ось → диапазон semver» в синтаксисе npm (`=`, `^`, `~`, `>=`, `>`, `<=`, `<`, пробел
— «и», `||` — «или»). Плагин объявляет **только те оси, которые использует**.

| Ось | Что значит | Кто объявляет | Кто сверяет |
|---|---|---|---|
| `steer-api` | протокол программ-помощников, хуков и подкоманд, формат событий evline, подстановки, файлы nft, команды сокета ([steer-api.md](steer-api.md)) | плагины с программами, подкомандами, службами, хуками или nft (в том числе с `so`) | менеджер при отборе; `steerd` при загрузке реестра и по `hello` помощника |
| `steer-abi` | ABI `.so` в `steerd` ([steer-abi.md](steer-abi.md)) | плагины с `steer.so` | менеджер; `steerd` перед `dlopen` и по полям структуры регистрации |
| `host-api` | host API панели ([host-api.md](host-api.md)) | плагины с `ui`, `themes`, `type: language` | splify2 перед `import()` |
| `splify2-api` | точки расширения бэкенда splify2 ([splify2-api.md](splify2-api.md)) | плагины с блоком `splify2` | splify2 |
| `splify2-luci` | интерфейс каркаса LuCI (зарезервировано, splify2-api 1.1) | плагины с `splify2.luci` | splify2 |
| `splify2` | версия панели — только если нужен её собственный rpc-метод | по нужде | splify2 |
| `steer-core` | **только нижняя граница** `>=X.Y.Z`: «нужна правка ядра, вышедшая в X.Y.Z» | по нужде | менеджер |

- **Тега «=версия ядра» нет ни у кого** (решение В10). Протоколы из дерева steer тоже объявляют
  `steer-api`, а не версию ядра. Схема отвергает у `steer-core` любой оператор, кроме `>=`. Почему
  оставлена нижняя граница — [open.md](open.md), О-3.
- Что даёт ядро, оно говорит само: `steer version --json` →
  `{"core":"2.1.0","api":"1.0","abi":"1.0"}`; splify2 — `host-api` в `build-id.txt` и в `plugins_list`.
- Правила версий осей одинаковы: **minor добавляет, major ломает**. Ядро с `api 1.3` исполняет
  плагины `^1.0`…`^1.3`; плагин `^1.4` на нём не ставится, а отказ называет числа («vless 2.2 требует
  steer-api ^1.4, у ядра 1.3»).
- Сегодняшняя сверка версий — строгое равенство: `mod_hello` (`steer/src/daemon/supd.c:323-340`)
  отвергает модуль, если `ver` из `hello` не равен `steer_engine_version()`. Для плагинов она
  заменяется сверкой `api` (см. [steer-api.md](steer-api.md), «hello»).

Отбор версии по тегам — [index.md](index.md), «Отбор».

## `arch`

- `"all"` — в архиве нет машинного кода (UI, переводы, темы, скрипты на shell/ucode).
- Иначе — список пакетных архитектур OpenWrt. Официальные сборки идут под 10 архитектур из
  `steer/build/arches.sh:7-18` (`mipsel_24kc` … `x86_64`, вместе с `aarch64_cortex-a72`).
- Архитектура роутера — та же строка, что у пакетов: `/etc/apk/arch` (apk) или старший приоритет
  `opkg print-architecture`. Архива под архитектуру роутера нет — версия не годится.
- Один `.s2p` — одна архитектура. Индекс держит архивы по архитектурам ([index.md](index.md)).

## `requires`: зависимости

```json
"requires": {
  "plugins": { "awg": "^2.1" },
  "system":  ["kmod-tun", "kmod-amneziawg|kmod-wireguard"],
  "kernel":  ["/dev/net/tun", "/sys/module/wireguard|/sys/module/amneziawg"]
}
```

- **`plugins`** — другие плагины (в том числе `type: library`) с диапазоном версий. Разрешаются по
  всему графу тем же отбором, что сам плагин; библиотеки ставятся раньше зависимых. Цикл — отказ с
  цепочкой имён. Зависимость ищется сначала в репозитории самого плагина, затем во всех по приоритету
  (`repos.d`), но **плагин обновляется только из того репозитория, из которого поставлен**.
- **`system`** — пакеты фидов OpenWrt. `a|b` — годится любой; если не стоит ни один, ставится первый.
  Ставит их менеджер через `apk add` / `opkg install` — единственный вызов чужой утилиты, без
  которого не обойтись (пакеты подписаны ключом OpenWrt). В `state.json` записывается, что поставил
  **менеджер**. Снятие плагина системные пакеты **не снимает**: чужой пакет — чужая настройка,
  человек мог поставить его и для своих целей. Раздел «Плагины» показывает «поставлено для
  плагинов, сейчас не нужно».
- **`kernel`** — пути, которые должны существовать после установки системных пакетов (`a|b` — любой).
  Не прошло — плагин не встаёт, отказ называет путь и пакет. Пример — recheck: без
  `kmod-nf-conntrack-netlink` очередь отвечает «Not supported» (PLUGINS.md 3.6, шаг 4).

## `conflicts`

Список `id`. Ставится только один из пары; отказ называет стоящий плагин. Объявлять с одной стороны
достаточно.

## `permissions`: права

Решение В6: **права у официального и стороннего репозитория одинаковые**. Плагин исполняется от root
(помощники, rpcd, `.so` в `steerd`), и подпись — это доверие автору, а не песочница. Права в
манифесте нужны для трёх вещей: показать человеку при установке, что плагин делает; дать ядру
проверить, что плагин пользуется только заявленным; подготовить этап 8 плана (понижение прав
помощников: `net.admin` → `CAP_NET_ADMIN` без root).

| Право | Что разрешает | Кто проверяет |
|---|---|---|
| `net.admin` | устройства, маршруты, сокеты с меткой | этап 8 (capabilities) |
| `nft` | файлы `steer.nft` и `kinds[].nft`, своя таблица nft | менеджер: файлы nft без права — отказ установки |
| `spec.transform` | хуки `pre_apply` и `kinds[].expand` | менеджер |
| `so` | `steer.so` — код в процессе `steerd` | менеджер; `steerd` |
| `http` | сеть наружу из помощников и rpc | этап 8 |
| `ctl` | команды сокета `steerd` (подписка на события, `status`, `apply`) | этап 8 |
| `system-packages` | `requires.system` | менеджер |
| `splify2.hooks`, `splify2.override`, `splify2.hide`, `splify2.deny` | хуки каркаса; замена и обёртка методов; скрытие экранов и видов; убрать метод из ACL ([splify2-api.md](splify2-api.md)) | splify2; `s2p lint` |
| `fs:<путь>` | запись вне каталогов плагина; каждый путь `keep` обязан иметь такое право | менеджер |

Свои каталоги плагин получает без прав: `/usr/lib/steer/plugins/<id>/` (только чтение),
`/etc/steer/plugins/conf/<id>/` (настройки, сохраняются всегда), `<state>/plugin/<id>/` (tmpfs).

## `resources`: ресурсы ядра

Плагин не зашивает числа меток, очередей, портов и таблиц. Сейчас зашивают: recheck — очереди
4350/4351 и метки `0x40000000`, `0xe0000000`, `0x1000`
(`recheck/integration/openwrt/root/usr/lib/recheck/recheck.sh:5-12`). Ядро выдаёт ресурсы по манифесту
и хранит выдачу постоянно (`/etc/steer/plugins/alloc.json`): после обновления плагина номера те же.

| Ключ | Что | Откуда ядро берёт |
|---|---|---|
| `mark_bits` | биты метки пакета вне поля steer | свободные биты (поле steer — `plat()->mark_mask`, `steer/src/model/marks.h:69-71`; соседи — mwan3 и Tailscale/pbr, `marks.h:30-48, 123`) |
| `queues` | номера NFQUEUE | диапазон ядра (см. [steer-api.md](steer-api.md), «Ресурсы») |
| `ports` | локальные порты TCP/UDP | диапазон ядра |
| `tables` | номера таблиц маршрутизации | ряд реестра (`steer/src/model/registry.c:17-28`) |

Ресурсы на каждый выход вида — в `kinds[].resources`. Подстановки в argv и nft — `{mark}`,
`{mark0}`…, `{queue0}`…, `{port}`…, см. [steer-api.md](steer-api.md). Кончился ресурс — отказ
называет, сколько всего и кем занято.

## `steer`: точки расширения ядра

### `steer.kinds[]` — виды выходов

```json
{
  "name": "tunnel:vless",
  "keys": "kinds/vless.schema.json",
  "caps": ["device", "mark", "ctmark", "engine-owned", "self-nat", "over", "tcp-probe", "flow-udp", "tcp-redir", "ipv6"],
  "helper": { "prog": "bin/vless", "cmd": "vless", "argv": ["vless", "{out}", "--conf", "{conf}"] },
  "check":  { "prog": "bin/vless", "argv": ["vless-check"], "timeout_s": 10 },
  "expand": null,
  "health": "events",
  "nft": [],
  "resources": { "ports": 1 },
  "texts": { "lan_only": null, "novia": null, "selfnat_why": "туннель сам подменяет адрес" }
}
```

| Поле | Что |
|---|---|
| `name` | имя вида в спеке. `tunnel:<протокол>` регистрирует протокол вида `tunnel` (`kind: tunnel, protocol: vless` — запись спеки v2, `steer/src/model/v2.c:44-56, 734-747`) |
| `impl` | `plugin` (умолчание) — вид целиком у плагина; `core` — код вида остаётся в ядре, плагин даёт допуск, зависимости и UI. `core` принимается только из официального репозитория и только для видов, которые ядро знает (в 2.1 — `awg`, решение В2) |
| `keys` | JSON Schema ключей выхода — подмножество из [`schema/kind-keys.schema.json`](../schema/kind-keys.schema.json). Неизвестный ключ — отказ, как сейчас у v2 (`steer/src/model/v2.c:610-631`) |
| `caps` | свойства вида — имена битов `enum kind_cap` (`steer/src/kinds/kind.h:40-67`): `device`, `mark`, `ctmark`, `engine-owned`, `self-nat`, `over`, `tcp-probe`, `flow-udp`, `ipv6`, `tcp-redir`. `KC_SKIP_ZAPRET` (`kind.h:47`) плагинам не выдаётся: zapret из ядра убран |
| `helper` | помощник на каждый выход вида — программа под супервизором `steerd`. `cmd` — имя помощника в журнале, `status` и событиях `helper-up`/`helper-down` (как `kind_helper.cmd`, `kind.h:96-110`) |
| `check` | проверка выхода сверх схемы (то, что сейчас делают `kind_ops.parse`/`check`, `kind.h:162-169`) |
| `expand` | хук разворота: выход вида превращается в выходы видов ядра (как `kind: warp` сейчас, `steer/src/model/v2.c:1133-1265`). Требует права `spec.transform` |
| `health` | как сторож судит о здоровье: `events` — по `up`/`down` помощника; `probe` — `up` с `watch:1` и есть приговор; `icmp`/`tcp` — общая проба ядра (`KC_TCP_PROBE`, `kind.h:48-50`) |
| `nft` | шаблоны nft на каждый выход (как `tgws_emit`, `steer/src/kinds/tgws.c:115-128`) |
| `resources` | ресурсы на каждый выход (`ports`, `queues`) |
| `texts` | `lan_only`, `novia`, `selfnat_why` — строки, которые общий код печатает о виде (`kind.h:143-152`) |

Протокол вызова `helper`, `check`, `expand` и формат `{conf}` — [steer-api.md](steer-api.md).

#### Ключи вида

Схема ключей — подмножество JSON Schema, которое ядро проверяет само, без сторонней библиотеки:
`type`, `enum`, `const`, `default`, `pattern` (POSIX ERE, `regcomp`), `minLength`/`maxLength`,
`minimum`/`maximum`, `items`, `minItems`/`maxItems`, `uniqueItems`, `properties`, `required`,
`additionalProperties` (только `false`/`true`), без `$ref`. Два расширения:

- `x-secret: true` — значение не печатается в `status`, `diag`, журнале, `explain` и в отказах;
- `x-path: etc|conf|abs` — строка есть путь к файлу: `etc` — относительно каталога спеки (как
  `subscription: sub/nl` сейчас, `steer/src/model/v2.c:214-220`), `conf` — относительно
  `/etc/steer/plugins/conf/<id>`, `abs` — только абсолютный. Ядро разворачивает путь до абсолютного,
  прежде чем отдать выход плагину.

**Слова для формы и условий (предложение).** Каркас рисует схему ядра (`steer spec-schema --json`) и схему
плагина **одним кодом**, поэтому схеме ключей вида (и схеме настроек `splify2.settings.schema`) нужны те же
слова `x-…`, что у ядра — формат и смысл
[`spec-schema.md`](https://github.com/splify2/steer/blob/main/docs/spec-schema.md), раздел «Формат»:

- `x-ref: {"section": "outputs", "also": ["direct"]}` — значение называет запись раздела (`outputs`, `lists`,
  `clients`, `dns.upstreams`); у массива стоит на `items`. Форма — выбор среди записей, не поле для имени;
- `x-one-or-list: true` — у массива годится одно значение вместо списка;
- `x-watch: true` (steer-api 1.1) — у ключа-пути: содержимое файла входит в подпись перезапуска помощника
  (переписанная подписка перезапускает клиент выхода);
- `x-when: {"transport": ["ws"]}` и `x-when-set: ["obfs"]` — ключ имеет смысл при таком значении соседа / когда
  записан сосед; `x-needs: {"device": ["for"]}` — при значении без этих соседей разбор отказывает;
- `x-example` — годное значение ключа (подсказка в форме; у ключа без него ядро берёт `default`, первое
  значение `enum` или значение по типу; у ключа с `x-ref` угадать имя записи нельзя — пишите `x-example`).

Что ядро делает при разборе ключей плагина (ядро steer, ветка `plugin-kindkeys`; до выхода такого ядра слова
отвергаются при установке):

1. принять слова `x-ref`, `x-one-or-list`, `x-when`, `x-when-set`, `x-needs`, `x-example` в схеме ключей
   и не отказывать на них при установке (сейчас слова вне списка — отказ); `s2p lint` принимает их по
   обновлённой `schema/kind-keys.schema.json`;
2. `x-one-or-list` — разбор принимает значение вместо списка из одного элемента (как у ключей ядра); слово ставят только
   на `type: array`, `minItems` при этом действует (одно значение — список из одного);
3. `x-ref` — разбор проверяет, что имя есть в разделе спеки или в `also` (отказ называет ключ, имя и раздел: `to[1]: «ghost» — в разделе lists такой записи нет`; проверка идёт, когда
   спека разобрана целиком, так что имя может стоять ниже по тексту; `section` — один из `outputs`, `lists`,
   `clients`, `dns.upstreams`, иначе схема вида отвергается);
   в схеме настроек плагина (там спеки нет) `x-ref` только подсказка для формы;
4. `x-when`, `x-when-set` — только подсказка для формы, разбор их не проверяет (ключ вне условия, как ключ
   без смысла, остаётся законным); `x-needs` — разбор отказывает, как у ключей ядра (`x-needs` из
   `spec-schema.md`): соседом считается ключ, записанный в спеке, умолчание схемы не в счёт; соседи — ключи той же
   записи, `"*"` — при любом значении;
5. `x-plugin` автор не пишет: ядро ставит его само при слиянии схемы вида в `spec-schema` (id плагина).

Общие ключи выхода (`kind`, `protocol`, `on_fail`, `over`, `ipv6`, `prefix`, `device`) разбирает ядро;
в схеме вида их нет, и плагин их не переопределяет. Ключи пула туннеля (`active`, `by`, `interval`,
`silence`, `pick`, `tolerance`, сейчас общий разбор — `steer/src/model/v2.c:651-656`) переходят к
протоколу: автор вписывает их в схему своего вида (без `$ref` на устройстве). Общий фрагмент
`kinds/tunnel-pool.schema.json`, который SDK вклеивал бы сам, **не написан**: формат ключа `by` и
сочетания ключей определяет ядро 2.1 (`steer/src/model/v2.c:654-694`), а до его выхода договора нет, поэтому
`s2p build` ничего не вклеивает.

### `steer.commands[]` — подкоманды `steer`

Ядро собирает таблицу «подкоманда → плагин, программа» из манифестов при старте и по `plugin-reload`;
своих команд протоколов у ядра 2.1 нет (прежняя таблица `CMD_MOD` снята), без плагина команды нет.

| Поле | Что |
|---|---|
| `name` | подкоманда: `steer <name> …` исполняет `<plugin>/<prog> <argv…> <слова человека…>` |
| `prog`, `argv` | программа и её первые слова; умолчание `argv` — `["<name>"]` |
| `help`, `usage` | справка `steer help` |
| `conf` | (steer-api 1.1) первое слово — имя выхода: ядро находит выход в спеке и передаёт программе `--conf` с его {conf} (steer-api.md, 1.4); спеку человека программа не читает. Слово с «/» — путь, его ядро передаёт как есть |
| `ctl` | команда доступна через сокет `steerd` «ребёнком» (steer `docs/ctl.md`, «Команды плагинов»): `timeout_s`; `args` — слова по порядку: вид строкой (`name`, `int`, `target`, `file`, `word`) или объектом `{"kind": "int", "flag": "--node", "min": -1, "max": 9999}` — число в пределах, которое ядро передаёт программе флагом (steer-api 1.1); `optional` — сколько последних слов можно опустить; `body` — `none` или `file` (тело запроса ядро кладёт во временный файл и передаёт путь последним словом), `body_max` — предел тела (умолчание 16 МиБ); `lock` — изменяющая (идёт в очереди с `apply`). Прежнее `ctl.spec` (передать `--spec` демона) снято в 1.1: выход программе даёт `conf` |

Имена подкоманд ядра (`apply`, `status`, `plugin` и остальные из `cli_lookup`) плагину не даются.

## `rpc`

```json
"rpc": { "prog": "rpc/recheck", "methods": {
  "status": { "access": "read" },
  "set":    { "access": "write", "timeout_s": 30 },
  "scan":   { "access": "write", "job": true }
} }
```

- splify2 заводит объект ubus `splify2.p.<id>` и ACL `splify2-p-<id>` из `access` (замена рукописного
  `list` и `case` в `splify2/files/usr/libexec/rpcd/splify2:506-716`).
- Вызов: `<plugin>/<prog> <метод>`, параметры — JSON в stdin, ответ — JSON в stdout, код 0. Код не 0 —
  `{"ok":false,"error":"<stderr>"}`. Срок — `timeout_s` (умолчание 30).
- `job: true` — метод долгий: диспетчер возвращает `{"job":"<id>"}` сразу, а результат отдаёт
  `splify2.plugin_job {id}`. Сейчас долгий `steer_module_add` — один блокирующий вызов под замком
  (`splify2/files/usr/libexec/rpcd/splify2:710`), и десктоп держит для него отдельный список `LONG`.
- Обработчик — shell, ucode или бинарник; права те же, что у rpcd (root).

## `ui`

`{"entry": "ui/index.js", "css": ["ui/style.css"], "desktop": true, "rail": false}` — ES-модуль, который
панель загружает `import()` и у которого зовёт `activate(host)`. Интерфейс плагина живёт в его карточке
во вкладке «Плагины» (слот `pluginSettings`). `desktop: false` — плагин не грузится в десктопе
(например, ему нужна сессия LuCI). `rail: true` — редкое исключение: плагину разрешён свой раздел в
полосе (слот `railSection`). Подробно — [host-api.md](host-api.md).

## `i18n`

- `dir` (умолчание `i18n`), `languages` — какие словари плагина есть: `i18n/<язык>.json`, плоский
  объект «ключ → строка» с подстановками `{имя}`. Хост ищет строку в языке человека, затем в `ru`,
  затем показывает ключ.
- **Название и описание плагина по языкам** — ключи `plugin.name` и `plugin.description` в словаре плагина
  (`i18n/<язык>.json`). Раздел «Плагины» берёт их на языке человека; нет языка — на `en` (каркас английский),
  нет и там — слова манифеста (`name`, `description`) на том языке, на котором они написаны. Поэтому
  в манифесте остаётся один основной текст, а переводы живут в словарях. `s2p lint` проверяет оба ключа в каждом
  заявленном словаре (предупреждение, у `--official` — отказ); официальному плагину нужны словари `en` и `ru`.
  Плагин, которого нет на роутере (каталог), показывается словами манифеста: словаря у него ещё нет.
- **Словарь бэкенда** — `i18n/backend/<язык>.json` (плоский «код → текст», подстановки `{имя}`): тексты отказов и сообщений rpcd-части,
  которые хост подставляет в ответ на языке каркаса ([splify2-api.md](splify2-api.md#тексты-для-человека)). В манифесте не объявляется:
  хост находит файл по каталогу у каждого включённого плагина. У `type: language` — словарь каркаса и официальных плагинов, у
  обычного плагина — его собственные коды.
- `host` — только у `type: language` (решение В9: переводы — плагины). Словарь строк **хоста** для
  языка: `{"en": {"file": "i18n/host/en.json", "name": "English", "host": "^26.11"}}`. `host` —
  каким версиям словаря панели он соответствует. В стандартной поставке splify2 — `ru` (вшит) и
  плагин `lang-en`.

## `libs`: общие библиотеки

Решение владельца (2026-10-25): **общие библиотеки, нужные нескольким плагинам (wolfSSL, стек
туннелей), ставятся одной общей зависимостью-плагином, а не копией в каждом.** Плагин-библиотека —
`type: library` с разделом `libs`:

```json
{ "id": "net1", "type": "library", "version": "1.2.0",
  "libs": [ { "soname": "libs2p-net.so.1", "file": "lib/libs2p-net.so.1", "abi": "1.2" } ] }
```

- **SONAME несёт major ABI библиотеки**, `abi` — major.minor. Правило то же, что у осей `compat`:
  minor добавляет экспорт (старые символы и их поведение остаются), major ломает и даёт новый
  SONAME.
- **id библиотеки несёт major:** `net1`, следующий несовместимый выпуск — `net2`. Так две major-версии
  стоят рядом, пока на `net1` ссылается хоть один плагин (на роутере у плагина одна версия, PLUGINS.md
  3.7). Версия плагина-библиотеки — `<major>.<minor>.<patch>`, и major версии равен номеру в `id`.
- **Зависимый плагин** пишет `"requires": {"plugins": {"net1": "^1.2"}}` и собирается с
  `DT_NEEDED libs2p-net.so.1` и `DT_RUNPATH`/`DT_RPATH` `$ORIGIN/../../net1/lib` (musl понимает
  `$ORIGIN`, `LD_LIBRARY_PATH` не нужен). Путь ставит компоновщик, а не упаковщик: `s2p cc --requires net1`
  (в `s2p.json` — `"requires": ["net1"]`) добавляет `-Wl,-rpath,$ORIGIN/../../net1/lib`; `s2p build`
  архив только собирает и ELF не правит. `s2p lint` отвергает `DT_NEEDED libs2p-<имя>.so.<N>`, если в
  `requires.plugins` нет `<имя><N>` (так связаны `libs2p-net.so.1` и `net1`) или у файла нет этого `RUNPATH`.
- **Обновление библиотеки** в пределах major идёт отдельно и в фоне, как у любого плагина; зависимые
  перезапускаются (помощники — подписью `{conf}`, куда входит версия всех библиотек из графа; `.so` в
  `steerd` — рестартом службы). Проверка здоровья библиотеки — здоровье всех зависимых: не здоровы —
  откат библиотеки.
- **Экспорт** библиотеки — свой файл версий (`LIBS2P_NET_1 { global: s2p_*; local: *; }`): все
  экспортируемые имена с приставкой `s2p_`, wolfSSL внутри скрыт. Иначе в процессе `steerd` имена
  совпали бы с libsteer и `libsteer-wolfssl` ядра, а musl версий символов не различает. Нынешний экспорт libsteer (367 символов, `steer/build/libsteer.map`) и внешний
  список коннектора (`steer/build/exports-ext.lst:8-27`) в обещание не входят.
- Какие библиотеки официальный репозиторий выносит так и почему ядро держит свою копию wolfSSL —
  [steer-abi.md](steer-abi.md), «Сервисы протоколам».

## Варианты: `variant` и `standalone`

Один плагин может выходить в нескольких **вариантах** сборки: тот же `id`, та же версия, те же виды и
подкоманды, разный состав. Повод — мини-роутеры (4 МБ флеша, 32 МБ памяти): там «ставится» и «места
нет» решают сотни килобайт. Так сделана сегодня мини-сборка моста Telegram: отдельный бинарник `stgws`
профиля `tgws` — только перехват Telegram и то, на чём он стоит (`steer/build.sh:334-366`,
`steer/src/profile/tgws.c:1-33`), «три четверти мегабайта там заметны».

| Поле | Что |
|---|---|
| `variant` | `full` (умолчание) — обычная сборка, зависит от библиотек-плагинов (`net1`); `lite` — облегчённая: статическая программа, в которую вкомпилировано только нужное (у моста — TLS 1.3 без QUIC, транспортов и стека TUN), без `requires.plugins` |
| `standalone` | вариант умеет работать **без `steer-core`**: `prog` — программа с мини-ядром (свой набор nft, метка, таблица, как профиль `tgws`), `init` — init-скрипт procd, `update` — мини-ядро само обновляет этот плагин в фоне |

Правила:

- В индексе вариант — ключ `assets` вида `<арх>@lite`; без `@` — `full` ([index.md](index.md)).
- **С `steer-core`** менеджер берёт `full`. Если на разделе плагинов не хватает места на `full` вместе с
  его библиотеками, а `lite` помещается — берёт `lite` и пишет причину в `state.json` («облегчённый
  вариант: на полный нет места — нужно 2,1 МБ, свободно 0,8 МБ»). Когда место появится, автообновление
  предложит `full`. Под `steer-core` вариант `lite` работает обычным помощником вида (`hello`, `{conf}`,
  evline) — `standalone` при этом не используется, свой init не ставится.
- **Без `steer-core`** (мини-роутер) плагин ставит и обновляет мини-ядро варианта `standalone`:
  `scripts/postinst` кладёт `init` в `/etc/init.d/<id>` (только если `steer-core` нет), мини-ядро
  обновляет **только свой плагин и только вариант `lite`** тем же циклом, что менеджер: подписанный
  индекс официального репозитория, `.stage`/`.prev`, проверка здоровья, откат ([s2p.md](s2p.md)).
  Код этого цикла — тот же код менеджера из libsteer, вкомпилированный статически.
- Варианты одной версии обязаны совпадать по видам, подкомандам, схемам ключей и `compat.steer-api`:
  спека и настройки не зависят от того, какой вариант стоит. `s2p lint` сверяет.
- `standalone` разрешён только официальному репозиторию: init-скрипт и обновление мимо `steer-core`
  — это ещё одна служба на роутере, и её надо держать в одной руке.

`[{"id": "midnight", "file": "themes/midnight.json"}]` — файл темы: `{"name", "light": {...}, "dark":

## `keep`, `scripts`, `health`

- `keep` — абсолютные пути, которые переживают sysupgrade и снятие без `--purge`. Каждый путь должен
  быть разрешён правом `fs:`. `/etc/steer/plugins/conf/<id>/` сохраняется всегда и в `keep` не
  пишется. Сводный список пишет `steer-core` в `/lib/upgrade/keep.d/steer-plugins` ([s2p.md](s2p.md)).
- `scripts.postinst <старая версия|"">` — после распаковки, до включения; с `--check` — только проверка,
  без изменений системы. `scripts.prerm <новая версия|"">` — перед снятием или заменой.
  `scripts.migrate <старая версия>` — перенос настроек прежнего формата (recheck:
  `/etc/splify2/recheck.conf` → `conf/recheck/`). Код не 0 — шаг не удался, менеджер откатывает.
- `health.timeout_s` — сколько ждать признаков здоровья после установки или обновления (умолчание 60).
  Что считается здоровьем — [s2p.md](s2p.md), «Проверка здоровья».

## Проверки при установке (сводка)

Менеджер отказывает, называя причину, если:

1. `schema` неизвестна или манифест не проходит `plugin.schema.json`;
2. `id`, вид, подкоманда или служба заняты другим плагином;
3. `compat` не выполнен ядром или панелью (с числами);
4. нет архива под архитектуру роутера;
5. не разрешились `requires.plugins` или стоит плагин из `conflicts`;
6. файлы nft, `pre_apply`/`expand`, `so`, `keep` без соответствующего права;
7. `impl: core` не из официального репозитория или для вида, которого ядро не знает;
8. не хватает места («нужно 1,8 МБ, свободно 0,9 МБ», [s2p.md](s2p.md)).
