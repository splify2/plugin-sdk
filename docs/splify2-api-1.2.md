# splify2-api 1.2 — что добавлено к 1.1

splify2 26.11 говорит splify2-api **1.2**. Прибавка к [splify2-api.md](splify2-api.md) и [splify2-api-1.1.md](splify2-api-1.1.md): плагин,
написанный по 1.0 и 1.1, работает без изменений. Плагину, которому нужно новое, пишут `compat.splify2-api: "^1.2"`.

Нужда: шлюз для приложений вне LuCI (Desktop API) уезжает из пакета `splify2` в плагин `desktop-api`
([SPLIFY2_PLATFORM.md](https://github.com/splify2/splify2), раздел 6). Шлюз — CGI веб-сервера, и плагину нужен шов, который
выставит его наружу.

## `splify2.cgi`: плагин выставляет CGI

```jsonc
"compat": { "splify2-api": "^1.2" },
"permissions": ["splify2.cgi"],
"splify2": { "cgi": ["cgi/splify2-api"] }
```

- Каждое значение — файл **прямо в каталоге `cgi/` плагина** (`cgi/<имя>`, имя — `[A-Za-z0-9._-]`, не с точки). Файл
  исполняемый (shebang): веб-сервер запускает его от root, поэтому нужно **право `splify2.cgi`**, и карточка плагина
  показывает его человеку при установке.
- `plugin_sync` (после установки, включения, отключения и снятия плагина и при установке пакета splify2) ведёт ссылку
  `/www/cgi-bin/<имя>` → `<каталог плагина>/cgi/<имя>` для каждого **включённого** плагина с правом и убирает остальные.
  Выключенный или снятый плагин не выставляет ничего: адрес перестаёт отвечать.
- Трогаются только ссылки, ведущие в каталог плагинов. Чужой файл с тем же именем не перекрывается.
- Состояние CGI (устройства, токены) плагин держит в `/etc/steer/plugins/conf/<id>/`: оно переживает обновление и
  sysupgrade и не пропадает при выключении плагина.
- `s2p lint`: путь `cgi/<имя>`, файл есть и исполняемый, право заявлено, `compat.splify2-api` не включает 1.0 и 1.1.

## Версии

- `PLUGIN_SPLIFY2_API` хоста — `1.2.0`.
- Строка `tests/compat/matrix.json`: SDK 1.4.0 — splify2 26.11.0 — splify2-api 1.2.0 (заглушка `splify2-1.2`).
